## ✨ Возможности

### 🌍 Погода и данные
- **Живой фон** — градиенты и canvas-эффекты под текущую погоду: дождь, снег, туман,
  облака, звёзды с падающими метеорами, молнии при грозе
- **Текущая погода** + 8 метрик: ощущается, ветер с порывами, влажность, видимость,
  давление с трендом, точка росы, УФ-индекс, осадки
- **Минутная точность** (Open-Meteo `minutely_15` + интерполяция):
  - статус «дождь закончится через 23 мин · в 15:47»
  - температура и «ощущается» плавно между часовыми срезами
  - график 24ч: тянешь точку пальцем/мышью — время идёт **по минутам**
  - окна дождя/снега/грозы на графике с метками `HH:MM–HH:MM`
- **Живое автообновление**: UI тикает каждую минуту без F5; сеть ~каждые 3 минуты
  (и сразу при возврате на вкладку)
- **Точность прогноза**: «Авто» = `best_match` + региональная модель
  (ECMWF/Европа, GFS/Сев. Америка)
- **График температуры · 24 часа**
  - поминутный scrub мышью и пальцем (точка на линии)
  - диагональная штриховка осадков **только под** кривой температуры
    (с поправкой на растяжение SVG — линии не «плывут»)
  - круглые бейджи 💧/❄/⚡ на линии, чипы `Дождь 14:15–17:45`
- **Почасовой** (24ч) и **16-дневный** прогноз + история 16 дней
- **Качество воздуха** — простым языком: «Мелкая пыль / Норма», лучший и худший час,
  цветная полоска на 24ч вместо µg/m³-жаргона
- **Опасная погода** — короткий баннер + уведомления:
  `Гроза · через 23 мин · 15:47`
  типы: гроза, град, ливень, снегопад, метель, гололёд, ветер/шторм,
  жара, мороз, туман, высокий УФ
- **Солнечная дуга** — восход/закат, долгота дня, фаза луны, «золотой час»
- **LifeSky-активности** — бег, мойка авто, прогулки (оценка 0–100)

### 🗺️ Карта и осадки
- Карта на **MapLibre GL** (CARTO + фолбэк OSM), выбор точки кликом
- **Карта осадков RainViewer**: прошлые ~2ч + nowcast ~1ч, dual-layer cross-fade
  (без мерцания), play/pause, скорость 0.5–3×, плотность, Live, автообновление
- **Умная ленивая загрузка** — на слабых устройствах MapLibre и модуль карты не
  грузятся при старте и докачиваются по первому тапу; на мощных — карта
  тихо предзагружается в фоне сразу после старта/согласия и отображается как раньше
- ⚠️ **Насколько верить радару** — см. раздел ниже

### 🧠 Smart Visibility — оптимизация рендеринга
- **Секции рендерятся по мере скролла** — каждая секция получает состояние:
  `active` (в viewport), `inactive` (далеко), `unloaded` (максимально далеко)
- **Debounced unloading** — при быстром скролле не дёргается (4 сек буфер;
  в Eco/low-режиме разгрузка срабатывает быстрее)
- **content-visibility: auto** — браузер пропускает рендеринг/layout/paint
  off-screen секций (основной выигрыш по CPU/GPU)
- **Реальное удаление тяжёлого DOM** — у далёких секций карточка отсоединяется
  от DOM и заменяется лёгким скелетоном (высота сохраняется, скролл не прыгает);
  при возврате карточка вставляется обратно без перерисовки, если данные не менялись
- **Ленивый re-render** — при обновлении данных разгруженные секции не перестраивают
  DOM, а помечаются «грязными» и перерисовываются только когда пользователь к ним
  возвращается
- **Интеграция с существующей FPS-системой** — в Eco-режиме отключаются все анимации секций

### 📲 PWA, офлайн и уведомления
- **PWA + офлайн**: service worker кеширует оболочку и последний прогноз
- **Установка на экран**: манифест, иконки, `beforeinstallprompt`, iOS-мета
- **Погодные уведомления** — локальные алерты (гроза, град, ливень, снег/метель,
  гололёд, ветер, жара/холод, туман, УФ) с минутной привязкой + Web Push ready

### 🎨 Удобство
- **3 языка** (RU / EN / ES) · **3 темы** (адаптивная / тёмная / светлая)
- Метрические/имперские единицы · модели Auto / ECMWF / GFS / ICON
- Поиск, избранное, недавние города, геолокация
- Live-обновление · клавиатура · `prefers-reduced-motion`

## 📡 Насколько можно верить карте осадков?

Карта осадков в LiveSky — это **реальные радарные снимки** [RainViewer](https://www.rainviewer.com/)
(агрегатор наземных метеорадаров + спутник), а не «картинка от нейросети».

| | |
|---|---|
| **Что это** | Мозаика радарных кадров ~каждые 10 мин: прошлое (~2ч) + nowcast (~1ч вперёд) |
| **Сильные стороны** | Хорошо видно, *где сейчас* идёт дождь/снег и куда движется фронт |
| **Ограничения** | Нет радара в океане/горах/редкой сети; nowcast — экстраполяция движения, не полный прогноз модели; на zoom > 7 тайлы upscale (данные до z7) |
| **С чем сравнивать** | Точечный nowcast Open-Meteo (`minutely_15`) на герое/графике — про «дождь *у вас* через N мин»; карта — про *картину по региону* |

**Практически:** для «брать ли зонт в ближайший час» карта + минутный статус — лучшая связка.
Для «будет ли дождь завтра в 18:00» смотрите почасовой/дневной прогноз (модели ECMWF/GFS/ICON),
а не радар.

## 🚀 Запуск локально

Проект полностью статический — достаточно открыть `docs/index.html`. Для работы
PWA/service worker и карт удобнее HTTP-сервер:

```bash
python3 -m http.server 8000 --directory docs
# → http://localhost:8000
```

### Установка как приложения (PWA)

- **Android / Chrome / Edge / Desktop** — значок «Установить» в адресной строке
  или кнопка «Установить приложение» в меню LiveSky
- **iOS Safari** — «Поделиться» → «На экран "Домой"»
- **Офлайн** показывается последний кешированный прогноз

### Сборка Android APK (Capacitor)

Нативный проект находится в `android/`. Требования для локальной сборки:
Node.js 22+, JDK 21+ и Android SDK 36.

```bash
npm ci
npm run cap:sync       # скопировать docs/ и обновить нативные плагины
npm run android:build  # debug APK
npm run android:open   # открыть проект в Android Studio
```

Debug APK появится в `android/app/build/outputs/apk/debug/app-debug.apk`.

Для Google Play используйте `npm run android:bundle` и настройте release-подпись через
локальный keystore — файлы `*.jks`, `*.keystore` и `android/key.properties` исключены из Git.
Иконки и splash-экраны вновь можно создать командой `./scripts/generate-android-assets.sh`
(нужен ImageMagick).

#### Производительность Android

APK отображает тот же интерфейс внутри **Android System WebView**, а сайт — непосредственно
в Chrome. Версии движка, GPU-композитинг и оптимизация `backdrop-filter`/Canvas на устройстве
могут отличаться, поэтому debug APK иногда работает тяжелее сайта. На слабых телефонах
выберите в меню **Производительность → Эконом**: приложение отключит погодный Canvas,
движущиеся фоновые пятна и снизит размытие карточек. Режим **Авто** также переключается на
облегчённый профиль, если FPS устойчиво падает.

## 🧩 Структура JavaScript

Основная логика сайта разделена на тематические модули в `docs/js/modules/`:

- `01-core.js` — DOM, состояние, хранилище, локализация и базовые helpers;
- `02-weather-data.js` — загрузка прогноза, AQI и геолокация;
- `03-rendering.js` — hero, метрики и общие рендереры;
- `04-chart.js` — график температуры и осадки;
- `05-hourly-alerts.js` — почасовой прогноз, дневной прогноз и hazard-алерты;
- `06-air.js` — качество воздуха;
- `07-effects.js` — темы, фоновые эффекты и canvas;
- `08-search-modals.js` — поиск, избранное и модальные окна;
- `09-lifecycle.js` — Smart Visibility;
- `10-bootstrap.js` — фасад ленивой карты `window.LiveSkyMap`, погодные
  уведомления, Capacitor-мост и единственный вызов `init()` приложения;
- `11-map-radar.js` — карты MapLibre и радар RainViewer. **Ленивый модуль**:
  подключается по первому запросу карты/радара, а не при загрузке страницы.

`docs/index.html` подключает модули `01–10` **обычными (classic) script-тегами**
последовательно. Это важно: модули используют общую область видимости, поэтому
их порядок нельзя менять. `10-bootstrap.js` завершает загрузку и единственный
вызывает `init()`.

### ⚡ Ленивая загрузка карты и радара (Этап 1)

Карта и радар — самая тяжёлая подсистема (MapLibre GL ~800 КБ JS) — полностью
убраны со стартового пути страницы:

| Путь | Что грузится | Объём |
|---|---|---|
| **Старт (eager)** | `i18n.js` + модули `01–10` (погода, график, hourly/daily, AQI, алерты, эффекты, поиск/модалки, Smart Visibility, bootstrap) | **267 557 Б** |
| **По требованию (lazy)** | `maplibre-gl.js` + `maplibre-gl.css` + `11-map-radar.js` | **893 267 Б** |

Раньше стартовый JS весил 1 083 913 Б — экономия на холодном старте **816 КБ (−75%)**
парсинга/исполнения JS, что особенно заметно на слабых Android/WebView.

Как это работает:

- первый тап по мини-карте, кнопка «Радар» или открытие полноэкранной карты
  вызывают фасад `window.LiveSkyMap` (`load / open / close / toggleRadar`);
- **умная предзагрузка для мощных устройств**: сразу после старта (или принятия
  соглашения) фасад тихо догружает карту в фоне (`shouldPrefetch`:
  `navigator.hardwareConcurrency` ≥ 4 и `navigator.deviceMemory` ≥ 4 ГБ;
  режим «Эконом» и детект низкого FPS всегда отключают предзагрузку; «Максимум» —
  включает; неизвестное железо считается мощным) — карта появляется на месте
  мини-карты практически как раньше, ничего не открывая без запроса пользователя;
- загрузчик вставляет `<script>` **ровно один раз** (один Promise на все
  конкурирующие вызовы), корректно обрабатывает `onload/onerror`, показывает
  статус загрузки на мини-карте, при сбое сети даёт toast с кнопкой повтора
  (фоновая предзагрузка при сбое молчит — ленивый путь остаётся рабочим);
- лениво подключаемый `maplibre-gl.css` вставляется **перед** `app.css` —
  тёмная тема контролов карты и атрибуции сохраняет приоритет каскада,
  а белая всплывашка с названием города на полноэкранной карте убрана вовсе;
- после загрузки пользователь сразу попадает в нужный экран — второй клик не
  нужен; повторные открытия/закрытия не плодят DOM, инстансы MapLibre, таймеры
  или обработчики (обработчики карты/радара вешаются один раз внутри модуля);
- ленивый загрузчик никогда не обходит согласие с условиями использования (ToS) —
  при заблокированном интерфейсе запросы карты отклоняются;
- `init()` приложения по-прежнему вызывается ровно один раз и не зависит от карты.

**Офлайн сохраняется:** service worker (namespace `livesky-v1.3-lazy-map`)
по-прежнему прекешит `11-map-radar.js`, MapLibre GL JS и CSS — после одного
онлайн-запуска оболочка полная и карта открывается офлайн (сами тайлы
CARTO/OSM/RainViewer офлайн могут отсутствовать — интерфейс деградирует
аккуратно, без JS-ошибок).

**Android/Capacitor:** `webDir` остаётся `docs/`, `cap:sync` копирует ленивый
файл в assets, относительные URL работают из `https://localhost`, нативный мост
и кнопка «Назад» не изменились — старт приложения в WebView больше не требует
карты. (Рекомендуется вручную замерить на устройстве: холодный старт до/после,
первое открытие карты, работу офлайн.)

`docs/js/app.js` больше не является bundle: это небольшой compatibility-loader
для старых HTML-встраиваний (он тоже подключает только eager-модули `01–10` —
карта грузится фасадом). Ничего собирать вручную после изменения модулей не нужно.

## 🛡️ Надёжность

- Все `fetch` с таймаутами (AbortController) — ни один запрос не зависает
- Watchdog загрузчика — экран загрузки не может остаться навсегда
- Аварийная панель с кнопками **«Перезагрузить»** и **«Сообщить об ошибке»**
- Автодоклад о багах: при ошибке сети/сбое появляется кнопка-баг, ведущая на GitHub Issues
- Санитизация настроек из localStorage · защита от устаревшего кеша (версии ассетов)

## 🔒 Приватность и лицензионный комплаенс

- **Ни одного запроса к сторонним доменам до согласия.** Шрифты, иконки,
  картографическая библиотека и флаги хостятся локально (`docs/assets/`);

- **Атрибуция поставщиков** (требования CC BY 4.0 / OSM / CARTO): блок в подвале
  с кликабельными ссылками + компактная атрибуция MapLibre на обеих картах.
- **Лицензии вендоров** приложены рядом с файлами: `assets/fonts/LICENSE-*`,
  `assets/vendor/maplibre-gl/LICENSE.txt`, `assets/vendor/phosphor/LICENSE`,
  `assets/flags/LICENSE`.
- Политика конфиденциальности сервиса версии 1.3 отражает фактическую архитектуру: резервные
  провайдеры геоданных (BigDataCloud, CARTO), локальное хранение истории городов
  (localStorage / Cache API).
