# LiveSky

[Открыть сайт](https://theflipper-spec.github.io/livesky/) · [Android-релизы](https://github.com/TheFlipper-spec/livesky/releases) · [Сообщить об ошибке](https://github.com/TheFlipper-spec/livesky/issues)

LiveSky — статическое погодное приложение для браузера и Android. Оно получает прогноз от Open‑Meteo, показывает ближайшие часы и дни, качество воздуха, карту осадков и работает как PWA. Сервер приложения не требуется: сайт можно развернуть на GitHub Pages или любом обычном статическом хостинге.

## Что есть в приложении

- текущая погода, почасовой прогноз и прогноз на 16 дней;
- температура, ощущаемая температура, ветер и порывы, влажность, давление, видимость, точка росы и УФ-индекс;
- минутный прогноз осадков, если он доступен у Open‑Meteo;
- интерактивный график температуры и осадков — на телефоне его можно прокручивать и изучать пальцем;
- карта MapLibre с подложкой OpenFreeMap и слоем радара RainViewer;
- качество воздуха с короткими пояснениями вместо перегруженных таблиц;
- поиск городов, избранное, история и определение местоположения по явному запросу пользователя;
- русский, английский и испанский языки; метрические и имперские единицы;
- тёмная, светлая и адаптивная темы;
- установка как PWA и нативная Android-оболочка на Capacitor.

Анимации фона помогают прочитать состояние погоды: дождь, снег, облака, туман, ночные звёзды и вспышки при грозе. Убран только слой крупных капель на карточках — он мешал интерфейсу; фоновая анимация дождя сохранена.

## Запуск локально

Нужен Node.js 22 или новее.

```bash
npm ci
npm run serve
```

Сайт откроется на <http://localhost:8000>. Для быстрой проверки без npm подойдёт и обычный статический сервер:

```bash
python3 -m http.server 8000 --directory docs
```

### Проверки

```bash
npm test
npm run build:js
```

`build:js` не создаёт бандл: модули подключаются напрямую как обычные script-теги. Команда проверяет синтаксис каждого файла и их общий порядок. `npm test` запускает smoke-тест в jsdom, включая загрузку данных, поиск, карту, PWA-настройки и Android-конфигурацию.

## Android

Android-проект находится в `android/` и использует Capacitor 8. Для локальной сборки нужны Node.js 22+, JDK 21 и Android SDK 36.

```bash
npm ci
npm run cap:sync
npm run android:build
```

Debug APK будет создан по пути:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

Чтобы открыть проект в Android Studio:

```bash
npm run android:open
```

### Release APK в GitHub Actions

Шаблон [android-release-workflow.template.yml](android-release-workflow.template.yml) предназначен для создания или замены release-workflow через интерфейс GitHub Actions. Скопируйте его содержимое в `.github/workflows/android-release.yml`: workflow соберёт именно код тега, проверит APK через `apksigner`, сохранит артефакт и прикрепит его к релизу.

Перед первым релизом добавьте в Secrets репозитория:

- `KEYSTORE_BASE64` — keystore в Base64;
- `KEYSTORE_PASSWORD`;
- `KEY_ALIAS`;
- `KEY_PASSWORD` — необязателен, если пароль ключа совпадает с паролем хранилища.

Без keystore workflow останавливается до сборки, а не публикует случайно неподписанный APK. Локальные `*.jks`, `*.keystore`, `android/key.properties`, APK и AAB исключены из Git.

## Устройство проекта

```text
docs/                         опубликованный сайт
├── index.html                разметка и подключение модулей
├── css/app.css               стили, темы и адаптивная вёрстка
├── js/
│   ├── i18n.js               переводы и WMO-коды погоды
│   ├── app.js                loader для старых встраиваний
│   └── modules/              логика приложения
│       ├── 01-core.js        состояние, DOM и хранилище
│       ├── 02-weather-data.js запросы к погодным API
│       ├── 03–06             рендер, график, алерты и AQI
│       ├── 07-effects.js     темы и ненавязчивые фоновые эффекты
│       ├── 08–10             поиск, жизненный цикл и запуск
│       └── 11-map-radar.js   карта и радар, загружаются по требованию
├── legal/                    пользовательское соглашение и приватность
├── assets/                   локальные шрифты, иконки, флаги и MapLibre
└── sw.js                     service worker
android/                      нативный Android-проект
scripts/                      служебные скрипты
tests/smoke.js                smoke-тест
```

Карта и MapLibre не попадают в критический путь загрузки. Модуль `11-map-radar.js` подгружается при первом открытии карты или радара; на подходящем устройстве он может тихо предзагрузиться после запуска. Service worker кеширует оболочку, последний прогноз и код карты, поэтому после первого посещения приложение остаётся полезным без сети. Сами картографические тайлы и радар в офлайне могут быть недоступны.

## Данные и приватность

- Прогноз, геокодирование и качество воздуха: [Open‑Meteo](https://open-meteo.com/).
- Радар осадков: [RainViewer](https://www.rainviewer.com/).
- Карта: [MapLibre GL](https://maplibre.org/), [OpenFreeMap](https://openfreemap.org/), [OpenStreetMap](https://www.openstreetmap.org/) и OpenMapTiles.

Передача координат нужна только для запроса погоды или обратного геокодирования. Подробности описаны в [политике конфиденциальности](PRIVACY.md) и [версии для сайта](docs/legal/privacy.html). В подвале и на карте оставлена обязательная атрибуция источников.

## Разработка

Если меняете модули, сохраняйте их порядок в `docs/index.html`: они работают в общей области видимости. После изменения файлов, которые кеширует PWA, обновляйте версию в `docs/sw.js`, чтобы старые кеши корректно удалились.

Пожалуйста, не добавляйте CDN без необходимости: основные шрифты, иконки и библиотеки уже лежат в `docs/assets/`. Это уменьшает зависимость от сторонних серверов до принятия пользовательского соглашения и делает офлайн-режим предсказуемее.
