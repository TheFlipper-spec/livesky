# LiveSky — аудит багов, улучшения и идеи

Дата: 14 августа 2026 · Ветка: `arena/01a0006c-livesky`

## Что было найдено и уже исправлено

### Логические баги

1. **Радар мог «застрять» без слоя.** `ensureLayer()` добавлял source и layer в одном `try`. Если `addSource` успевал, а `addLayer` выбрасывал ошибку (карта ещё не закончила загрузку стиля), то на следующей попытке `getSource('radar')` уже возвращал существующий source → код уходил в ветку `setTiles` и **никогда** не добавлял слой.
   → **Исправлено**: source и layer проверяются/добавляются независимо; повторная попытка всегда может довести добавление слоя до конца.

2. **FPS-детектор не запускался, если приложение стартовало в режиме «Максимум».** `PERF.start()` вызывался только в `init()` при `effects !== 'full'`. Если пользователь загрузил приложение с сохранённым «full», а потом переключил на «Авто» — детектор так и не стартовал.
   → **Исправлено**: `PERF` получил флаг `started` и стартует при переключении на «Авто».

3. **Деление на ноль в спарклайнах качества воздуха.** `airSpark()` и `airTrendSVG()` делили на `(length - 1)` — при серии из одного кадра получался `NaN` (сломанный график).
   → **Исправлено**: защита `Math.max(1, length - 1)` / `Math.max(2, length)`.

4. **Дублирующее сообщение при офлайне.** `bindEvents` показывал тост «Ошибка сети» одновременно с офлайн-баннером (два сообщения подряд).
   → **Исправлено**: офлайн-состояние показывает только баннер; тост оставлен для реальных ошибок запросов.

### Визуальные баги

5. **Кнопка «Радар» перекрывалась панелью на узких экранах.** Панель занимает почти всю ширину (`min(640px, 100vw-28px)`), и на мобильном кнопка внизу слева попадала под панель.
   → **Исправлено**: на экранах ≤720px кнопка скрывается, пока панель открыта (у панели есть своя кнопка закрытия).

## Найденное, что стоит исправить в будущем (не критично)

- **`updateHero`** читает `feels` и `now`-переменные, которые не используются (мёртвый код).
- **`LOC_SHORT`** в `app.js` не используется (лишняя константа).
- **Двойная отрисовка при смене качества**: обработчик эффектов может дважды вызвать `applyEffects()`.
- **`radar` play** перегружает тайлы при каждом кадре через `setTiles` — при длинной анимации это много запросов. Можно кешировать уже загруженные кадры (как в официальном примере RainViewer — отдельные source+layer на каждый кадр).

## Что можно улучшить (полировка)

1. **Прелоад/кеш кадров радара.** Сейчас `setTiles` каждый кадр. Кешировать загруженные кадры — анимация станет плавнее и без «мигания».
2. **Прогноз осадков на таймлайне.** Подписи «−2ч, −1ч, Сейчас, +30м» вместо голого времени — сразу видно, прошлый это кадр или nowcast.
3. **Радар на маленькой карте.** Добавить кнопку радара и на превью-карту (или сделать радар доступным с главного экрана, а не только в полноэкранной карте).
4. **Авто-переключение opacity при play** — мягкое появление слоя, а не резкая смена тайлов.
5. **Показатель «осадки сейчас» в шапке радара** — читать `precipitation` из прогноза и подписывать кадр.
6. **Доступность**: aria-атрибуты для слайдера радара уже есть, добавить `aria-valuetext` с датой/временем кадра.

## Идеи (приоритет-вау)

1. **Сравнение двух городов** — бок-о-бок температуры/осадков (в плане «Приоритет 2»).
2. **Погода вдоль маршрута** — мини-таймлайн осадков/ветра на маршруте.
3. **График с диапазонами 48ч / 7 дней** — переключатель на существующем графике.
4. **Push-уведомления о грозе/дожде** — Web Push (нужен бэкенд) или локальная проверка при загрузке.
5. **«Умный» будильник погоды** — слот «проснуться до дождя» (связать с LifeSky-активностями).
6. **Радар поверх превью-карты** одним кликом, с автоцентром на текущем городе.
7. **Офлайн-мемо**: при офлайне показывать время последнего обновления прогноза, чтобы было понятно «свежесть» данных.
8. **Скриншот-тесты (Playwright)** в CI — ловит визуальные регрессии вида «обрезанной иконки».
